## 项目要回答的问题

电商平台的核心经营问题是：**流量进来了，为什么没有转化成成交？**

本项目基于用户行为流水（浏览 `pv` / 收藏 `fav` / 加购 `cart` / 购买 `buy`），回答三个业务问题：

1. 用户从浏览到购买，每一步流失多少？**哪个环节最该优化？**
2. 新用户留下来了吗？**留存曲线是什么形态？**
3. 哪些类目是「**高流量低转化**」，值得优先投入优化资源？

## 核心结论

> 面试官通常只读这一段。每条结论都带数字，每条都配了行动建议。

### 1. 瓶颈在成交链路，不在获客

整体购买转化率 **7.63%**，漏斗中流失最严重的是 **「加购 → 购买」环节，流失率 80.94%**。
用户已完成加购这一强意向动作却未成交——说明**获客没问题、商品认知没问题，问题出在成交链路本身**。

> **行动**：排查运费感知、精简支付步骤、对加购用户做 24 小时定向触达。

### 2. 数码电子是最大机会点

占全站 **15.04%** 的流量，转化率仅 **4.54%**，低于全站类目均值 5.72%，缺口 **1.18 个百分点**——
这是优化收益最高的单一类目。

> **行动**：排查该类目详情页图片质量、参数完整度、买家秀数量与定价竞争力。

### 3. 用户质量没问题，缺的是召回机制

次日留存 **34.15%**，7 日留存降至 **11.47%**；但复购率高达 **74.72%**。
留存衰减快、复购却很稳 —— 说明留下来的用户是优质用户，**缺的是把新用户拉回来的机制**。

> **行动**：建设首单后 7 天内召回触达序列（D1 权益提醒 / D3 关联推荐 / D7 复购券）。

### 4. 流量高度集中在晚间三小时

20–22 点贡献全天 **30.8%** 的浏览量，峰值在 21 点（**11.21%**）；凌晨 1–5 点合计不足 2%。
周末人均浏览深度 **8.03** 次，高于工作日 **7.01** 次（**+14.6%**）。

> **行动**：运营动作集中投放 19–22 点；客服按同时段排班。

### 5. 再营销池规模清晰

各类目「加购未购买」人群合计 **13,729 人次**，其中女装规模最大（2,239 人次）。
这批人已完成加购，转化成本远低于新客。
另有 **3,439 名（17.20%）「高活跃浏览」用户**行为活跃却几乎不购买，是最值得攻坚的转化池。

## 快速开始

**不需要安装任何第三方库**（不需要 pandas / numpy / matplotlib）。


> **环境要求**：Python 3.8+。Windows / macOS / Linux 均可。

### 用条件聚合替代多个子查询

漏斗分析需要同时算出四层人数。直觉做法是写四个子查询，但那意味着四次全表扫描。
本项目用 `COUNT(DISTINCT CASE WHEN ... THEN user_id END)` 在**一次扫描**中同时得出四个指标：

```sql
SELECT
  COUNT(DISTINCT CASE WHEN behavior_type = 'pv'   THEN user_id END) AS browse_users,
  COUNT(DISTINCT CASE WHEN behavior_type = 'fav'  THEN user_id END) AS fav_users,
  COUNT(DISTINCT CASE WHEN behavior_type = 'cart' THEN user_id END) AS cart_users,
  COUNT(DISTINCT CASE WHEN behavior_type = 'buy'  THEN user_id END) AS buy_users
FROM user_behavior;
```

在亿级数据量下，这个写法的性能差异是数量级的。

### 指标分母必须去重到「人」

转化率衡量的是**人的转化**，不是**次的转化**。
若用 PV 作分母，一个用户反复浏览会稀释转化率，指标就没有业务含义。
因此所有转化率类指标统一使用 `COUNT(DISTINCT user_id)`。

### 分母为 0 返回 NULL 而不是 0

返回 0 会参与后续的平均值计算，把真实水平拉低；
返回 NULL 会被数据库聚合函数自动排除，不污染结果。统一用 `NULLIF(x, 0)` 实现。

### 类目转化率必须加样本量门槛

所有类目级指标统一加 `HAVING browse_u >= 100`。
一个只有 5 名访客的类目出现 1 笔购买就会被算成 20% 转化率——这是统计噪音而非洞察，
不设门槛的排名会直接误导选品决策。

### 口径一致性：两个转化率不能混用

| 口径 | 数值 | 定义 |
|---|---|---|
| 平台级转化率 | **7.63%** | 按「人」在平台级去重（用户浏览多个类目只计 1 人） |
| 类目口径均值 | **5.72%** | 按「人 × 类目」统计，跨类目用户会被重复计入分母 |

两个数字都对，但**不能混用**——做平台级结论用前者，做类目横向对比用后者。

## 踩坑记录

> 这一节是这个项目最有价值的部分：**这些坑在真实项目里同样会遇到**。

### 坑 1：时区偏移导致业务高峰被错误定位

原始时间戳是 UTC 纪元值，直接按 UTC 解读会**偏移 8 小时**：

| 口径 | 定位到的峰值时段 |
|---|---|
| 未做时区换算 | 12–14 点 ❌ |
| +8 小时换算后 | **20–22 点** ✅ |

若不做换算，运营推送时间会整体错位 8 小时，直接影响策略效果。

> **实操细节**：`datetime.timestamp()` 已经按本地时区完成换算，
> 生成数据时**不可再手动减 8 小时**，否则会「负负得正」变成双重偏移。
> 这个坑我在本项目实际踩了一次——第一版修完之后峰值依然在 12–14 点，排查才发现是两边各减了一次。

### 坑 2：留存曲线不衰减 = 数据有问题

第一版模拟数据的留存曲线几乎是平的（D1 34.7% → D7 29.5%），明显不符合真实用户行为。
排查发现是活跃日被均匀撒在整个观察窗口导致的。
改为「首访后按衰减概率激活」后，曲线呈现正常衰减形态（D1 34.15% → D7 11.47%）。

> **经验**：留存曲线不衰减，通常不是业务好，而是数据生成 / 采集逻辑有问题。

### 坑 3：转化率过高是不真实信号

第一版数据的整体转化率高达 **37%**，远超真实电商的 **2–8%** 区间。
这是数据模型里购买概率设置过高导致的。修正后为 **7.63%**，落在合理区间。

> **经验**：拿到数据先做「常识校验」——转化率、留存率、客单价这类指标都有行业基准区间，
> 偏离太远说明数据本身有问题，而不是发现了业务机会。

### 坑 4：去重人数不能跨期相加（最隐蔽的一个）

看板第一版把「每日去重访客数」直接相加当作区间访客数，得到 **53,570**——
而真实的区间独立访客只有 **19,816** 人，**虚高 2.70 倍**。
连带影响更严重：转化率被算成 **2.82%**，真实值是 **7.63%**。

| 指标 | 错误做法（日 UV 相加） | 正确做法（区间去重） |
|---|---|---|
| 访客数 | 53,570（人次） | **19,816**（独立用户） |
| 购买转化率 | 2.82% | **7.63%** |

**根因**：`COUNT(DISTINCT user_id)` 是**非加法指标**（non-additive measure）。
一个用户 5 天活跃，在 5 个日期里各被计 1 次，相加就是 5，但真实只有 1 个人。
能安全相加的只有 PV、订单数这类**计数型**指标。

**正确做法**：
- 对固定的时间区间**预先精确计算**去重人数（本项目采用）
- 或在 BI 工具中保留用户级明细，在查询时实时去重（Tableau 的 `COUNTD` 就是这样工作的）

> **经验**：任何 `DISTINCT` 类指标在跨维度汇总时都必须重新计算，不能从下一级粒度加总上来。

## 迁移到 MySQL

`sql/` 目录下是 **MySQL 8 版脚本**，只需替换少量方言函数：

| 本演示（SQLite） | MySQL 8 |
|---|---|
| `strftime('%H', ts, 'unixepoch')` | `HOUR(FROM_UNIXTIME(ts))` |
| `julianday(a) - julianday(b)` | `DATEDIFF(a, b)` |
| `TEXT` | `VARCHAR` / `DATE` |
| `csv.reader` 导入 | `LOAD DATA INFILE` |

## 数据说明

本项目 `data/` 下的数据由 `01_generate_data.py` **程序化生成**，用于演示完整分析链路。

生成逻辑刻意贴近真实电商的用户行为特征，包含：

- **用户分层**：A-高频购买 / B-中频 / C-低频猎奇 / D-高活跃低转化 / E-沉睡，五档差异化活跃度与购买概率
- **类目差异**：10 个类目各有不同的流量权重、浏览深度与转化倾向
- **时段规律**：符合国内电商的双峰分布（午间小峰 + 晚间大峰，峰值 21 点）
- **周末效应**：周末活跃度与浏览深度均高于工作日
- **留存衰减**：新用户按衰减概率回流，而非均匀活跃

> ⚠️ 数据为**模拟生成**，不等同于任何真实平台的数据，仅用于方法与链路演示。
> 若替换为真实数据（如公开数据集），只需修改 `01_generate_data.py` 或直接在 `02_build_db.py` 中改为导入你自己的 CSV。
