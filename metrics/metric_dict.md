# 指标字典 · 电商用户行为分析

> 本文件是项目核心产出之一。数据分析岗 JD 中「指标计算口径和指标体系」出现频率极高（近期样本 4/5），
> 这份文档就是对该能力的直接证明。

## 使用说明

每个指标必须写清六个要素：**名称、业务含义、计算公式、分子口径、分母口径、边界处理**。
边界处理最容易被忽略，也最能体现分析的严谨性。

---

## 一、流量类指标

### 1.1 UV（独立访客数）

| 项 | 内容 |
|---|---|
| 英文名 | uv |
| 业务含义 | 统计周期内产生过任意行为的去重用户数，衡量平台覆盖的用户规模 |
| 计算公式 | `COUNT(DISTINCT user_id)` |
| 分子口径 | 该周期内出现过的 user_id 去重计数 |
| 分母口径 | 无 |
| 统计周期 | 按日 / 按周 / 按类目 |
| 边界处理 | 无数据时返回 0；同一用户跨天活跃在各天分别计入 |
| 数据来源 | user_behavior |
| 备注 | 注意与「登录用户数」区分，本数据无登录行为 |

### 1.2 PV（页面浏览量）

| 项 | 内容 |
|---|---|
| 英文名 | pv |
| 业务含义 | 全站内容被浏览的总次数，衡量内容消费规模 |
| 计算公式 | `SUM(behavior_type = 'pv')` |
| 分子口径 | behavior_type = 'pv' 的记录行数 |
| 分母口径 | 无 |
| 边界处理 | 同一用户重复浏览同一商品重复计数（这是 PV 的设计本意） |

### 1.3 人均浏览深度

| 项 | 内容 |
|---|---|
| 英文名 | pv_per_uv |
| 业务含义 | 平均每个访客浏览了多少商品，衡量内容吸引力与推荐精准度 |
| 计算公式 | PV ÷ UV |
| 边界处理 | UV = 0 时返回 NULL，**不返回 0**——返回 0 会拉低均值、扭曲结论 |
| 数据来源 | 由 PV 与 UV 派生 |

## 二、转化类指标（漏斗核心）

> 转化率类指标的共同原则：**分子分母都要去重到「人」**。
> 如果用次数当分母，一个用户反复浏览会稀释转化率，指标失去业务含义。

### 2.1 购买转化率

| 项 | 内容 |
|---|---|
| 英文名 | purchase_conversion_rate |
| 业务含义 | 访客中最终产生购买行为的用户占比，衡量从流量到成交的整体效率 |
| 计算公式 | 购买人数 ÷ 浏览人数 |
| 分子口径 | behavior_type = 'buy' 的**去重 user_id 数** |
| 分母口径 | behavior_type = 'pv' 的**去重 user_id 数** |
| 边界处理 | 浏览人数为 0 时返回 NULL，不返回 0 |
| 数据来源 | user_behavior |

### 2.2 加购率

| 项 | 内容 |
|---|---|
| 计算公式 | 加购人数 ÷ 浏览人数 |
| 分子口径 | behavior_type = 'cart' 的去重 user_id 数 |
| 业务含义 | 衡量商品详情页的说服力，加购率高说明商品本身吸引力强 |
| 边界处理 | 分母为 0 返回 NULL |

### 2.3 收藏率

| 项 | 内容 |
|---|---|
| 计算公式 | 收藏人数 ÷ 浏览人数 |
| 分子口径 | behavior_type = 'fav' 的去重 user_id 数 |
| 业务含义 | 衡量用户的"潜在购买意愿"，收藏但未购买是重要的再营销人群 |

### 2.4 全链路转化率

| 项 | 内容 |
|---|---|
| 计算公式 | 购买人数 ÷ 总访客数 |
| 业务含义 | 从进站到成交的端到端效率，是漏斗的最顶层指标 |
| 与 2.1 的区别 | 2.1 以浏览为起点；本指标以"任意行为"为起点，分母更大，数值更低 |

## 三、用户类指标

### 3.1 次日留存率

| 项 | 内容 |
|---|---|
| 英文名 | d1_retention_rate |
| 业务含义 | 新用户在次日仍活跃的比例，衡量产品黏性与拉新质量 |
| 计算公式 | 第 2 天仍活跃的新用户数 ÷ 当日新增用户数 |
| 分子口径 | `DATEDIFF(活跃日, 注册日) = 1` 的去重 user_id 数 |
| 分母口径 | 该注册日的去重 user_id 数 |
| 边界处理 | 分母为 0 返回 NULL；注册日当天算 D0 不算留存 |
| 关键说明 | 用 `DATEDIFF` 而非直接比较日期，这样「次日」「7 日」是同一套逻辑，只改参数即可扩展 |

### 3.2 复购率

| 项 | 内容 |
|---|---|
| 计算公式 | 购买次数 ≥ 2 的用户数 ÷ 有购买行为的用户数 |
| 分子口径 | `COUNT(behavior_type='buy') >= 2` 的 user_id 数 |
| 分母口径 | 存在购买行为的去重 user_id 数 |
| 业务含义 | 衡量用户忠诚度与商品复购属性 |

### 3.3 用户活跃分层

| 分层 | 判定口径 | 运营含义 |
|---|---|---|
| A-高频购买 | 购买次数 ≥ 3 | 核心用户，重点维护 |
| B-有过购买 | 购买次数 1～2 | 潜在复购人群，可做复购触达 |
| C-高活跃浏览 | 浏览 ≥ 20 且未购买 | 高意向未转化，重点转化对象 |
| D-一般活跃 | 浏览 5～19 | 普通用户 |
| E-低活/沉默 | 浏览 < 5 | 流失风险人群 |

**分层设计说明**：阈值（3 / 20 / 5）不是拍脑袋定的，应结合数据分布分位数调整。
面试被问到时，可以答："我按购买次数和浏览次数的分位数切分，保证各层用户量不出现极端失衡。"

## 四、商品与类目类指标

### 4.1 类目转化率

| 项 | 内容 |
|---|---|
| 计算公式 | 类目购买人数 ÷ 类目浏览人数 |
| 边界处理 | 分母为 0 返回 NULL；**用 `HAVING browse_u >= 100` 过滤样本量过小的类目**，避免统计噪音干扰排名 |

### 4.2 类目流量占比

| 项 | 内容 |
|---|---|
| 计算公式 | 类目 PV ÷ 全站 PV |
| 业务含义 | 判断流量结构是否健康，识别过度依赖的类目 |

### 4.3 高流量低转化类目（核心分析产出）

| 项 | 内容 |
|---|---|
| 判定口径 | 流量占比 > 2% 且 转化率 < 全站平均转化率 |
| 业务含义 | 有流量但成交差，是最该优先优化的一类，因为优化收益最大 |
| 行动建议方向 | 检查该类目的商品定价、详情页质量、评价口碑、运费政策 |

## 五、口径设计的三个通用原则

1. **人去重，次不去重。**
   人数类指标（转化率、留存率）必须 `COUNT(DISTINCT user_id)`；次数类指标（PV）不去重。

2. **分母为 0 返回 NULL，不返回 0。**
   返回 0 会参与后续平均值计算，稀释真实水平；NULL 会被数据库自动排除在聚合之外。

3. **样本量不足不下结论。**
   转化率类指标必须加 `HAVING` 门槛。一个只有 3 个访客的类目转化率 33%，这是噪音不是洞察。
